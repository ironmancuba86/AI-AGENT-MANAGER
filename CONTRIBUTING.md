# Contributing

## Before you contribute

- Read the README.
- Read the relevant docs folder before editing.
- Do not invent claims, metrics, or security guarantees.
- Keep changes scoped to one purpose per PR.

## Pull request expectations

- Small, reviewable changes.
- Clear summary of intent.
- Link to the relevant doc or prompt.
- No unrelated refactors.

## Documentation standards

- Use concise markdown.
- Keep enterprise tone.
- Prefer specific language over hype.
- If a file is security-sensitive, request review from the code owners.
